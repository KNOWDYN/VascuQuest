# HEMOSPACE

**Status:** integrated VascuQuest scientific operation mode  
**Namespace:** `vascuquest.hemospace` / `vascuquest hemospace`  
**Canonical dataset:** PWDB Zenodo record `3275625`

## Purpose

HEMOSPACE builds a comprehensive, provenance-aware **Virtual Cardiovascular Record** for one PWDB virtual subject. The record is a scientific description of a simulation instance, not a medical chart and not a human digital twin.

HEMOSPACE answers:

> What is scientifically knowable about this virtual cardiovascular system from canonical PWDB source data and defensible calculations based on those data?

The operation deliberately separates what is explicit in PWDB from what is reconstructed, derived, inferred, or modelled.

## Architecture

HEMOSPACE is a VascuQuest sub-package. It reuses:

- the verified PWDB artifact acquisition/cache layer;
- the strict `SubjectCSVTable` source reader;
- canonical VascuQuest subject identity;
- existing geometry and waveform access;
- the existing `Q = U*A` reconstruction;
- the existing evidence/provenance philosophy;
- the qualified Virtual Disease implementation without modifying its numerical physics.

HEMOSPACE does **not** duplicate the PWDB dataset backend or fork the disease solver.

## Record depths

### `scalar`

Reads every numeric subject field from all five subject-indexed canonical PWDB tables:

1. `pwdb_model_configs.csv`
2. `pwdb_model_variations.csv`
3. `pwdb_haemod_params.csv`
4. `pwdb_pw_indices.csv`
5. `pwdb_onset_times.csv`

Unlike the compact core VascuQuest schema, HEMOSPACE does not discard source fields merely because they are not promoted to a permanent core quantity. Known fields receive explicit cardiovascular semantics; unknown-but-numeric fields remain traceable source facts under stable source-derived identifiers.

### `geometry`

Adds the full subject-specific vascular network geometry and bounded deterministic geometric summaries:

- segment count;
- summed source-segment length;
- minimum and maximum represented endpoint diameter;
- approximate represented lumen volume using circular conical-frustum segments.

The volume is a geometric approximation, not measured blood volume.

### `comprehensive`

Adds common-site waveform characterization for all PWDB measurement sites and source signals `P`, `U`, `A`, and `PPG`, plus `Q = U*A` volumetric-flow summaries.

Raw waveform samples remain available through the ordinary VascuQuest waveform API/CLI. HEMOSPACE stores compact summaries rather than duplicating hundreds of megabytes of source samples inside each record.

## Evidence semantics

Each `KnowledgeItem` carries one evidence class:

- `SOURCE` — directly read from a canonical PWDB artifact;
- `RECONSTRUCTED` — exactly reconstructed from aligned source quantities;
- `DERIVED` — calculated using an explicit mathematical/physiological definition;
- `INFERRED` — estimated through a separately qualified inference method;
- `MODELLED` — generated by an explicit research model/operator.

HEMOSPACE v1 does not relabel derived quantities as source truth.

## Generative physiology

`pwdb_model_variations.csv` is treated as first-class knowledge. Its values are prescribed deviations in model inputs measured in standard deviations from the age-specific mean. HEMOSPACE exposes the ten design axes:

- `DIA` — large-artery diameter;
- `HR` — heart rate;
- `LEN` — proximal aortic length;
- `LVET` — left-ventricular ejection time;
- `MBP` — mean blood pressure;
- `PVC` — peripheral vascular compliance;
- `PWV` — arterial stiffness / pulse-wave velocity;
- `RFV` — aortic-root reverse-flow volume;
- `SV` — stroke volume;
- `PFT` — aortic-root peak-flow time.

These are **design-space coordinates of the virtual population**, not clinical z-scores measured from a patient.

## Initial deterministic derivations

HEMOSPACE currently adds only bounded, transparent derivations whose inputs are already present:

- cardiac-cycle duration from heart rate;
- cardiac output reconstructed from heart rate and stroke volume;
- discrepancy between reconstructed and source cardiac output as a consistency diagnostic;
- pulse pressure reconstructed from paired systolic and diastolic pressure fields where available;
- a system-level hydraulic-power approximation from mean pressure and cardiac output;
- deterministic geometry summaries;
- waveform summaries and reconstructed-flow summaries at common sites in comprehensive mode.

The catalogue will expand only when an added quantity has a clear scientific definition, units, required inputs, assumptions, validation method, and endovascular research value.

## CLI

```bash
vascuquest hemospace explain

vascuquest hemospace record \
  --subject 2104 \
  --source /path/to/pwdb \
  --offline

vascuquest hemospace record \
  --subject 2104 \
  --depth geometry \
  --source /path/to/pwdb \
  --offline \
  --output subject-2104.json

vascuquest hemospace record \
  --subject 2104 \
  --depth comprehensive \
  --source /path/to/pwdb \
  --offline

vascuquest hemospace coverage \
  --subject 2104 \
  --source /path/to/pwdb \
  --offline
```

## Python

```python
from vascuquest.hemospace import open_hemospace

hs = open_hemospace(source="/path/to/pwdb", offline=True)
record = hs.record("2104", depth="geometry")
payload = record.to_dict()
```

## Knowledge closure

The record reports scalar source coverage explicitly:

- number of source fields encountered;
- number exposed as source knowledge;
- number missing for the selected subject;
- source tables used;
- number of reconstructed/derived items;
- whether geometry and waveform enrichment were completed.

This makes source coverage auditable rather than relying on a visually impressive record.

## What HEMOSPACE refuses to invent

The output contains an explicit `unavailable_information` section for facts not identifiable from PWDB alone. Examples include:

- biological sex where not encoded;
- smoking history;
- genetics;
- renal function;
- medication history;
- symptoms;
- plaque composition;
- thrombotic state;
- longitudinal life history;
- future clinical event risk.

Age groups must not be reinterpreted as serial observations of one virtual individual.

## Scientific boundary

A VascuQuest `VirtualSubject` remains a simulation instance. HEMOSPACE enriches scientific knowledge *about that simulation instance*; it does not convert it into a real patient, clinical digital twin, diagnosis, prognosis, or complete human physiology model.

The governing rule is:

> HEMOSPACE asks what additional scientifically meaningful information is identifiable from available data, not what arbitrary mathematical features can be calculated from them.
